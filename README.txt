Zombie Army Trilogy - DT NextBots

This project replaces the Zombie Army 1 assets while retaining the existing
DT Base director, navigation, crowd, hearing, recovery and performance systems.
It contains the common soldier, Skeleton, Suicide Grunt and Armored Heavy, fresh Trilogy
equipment/materials/named audio, native dismemberment and occasional lazy firing.
The runtime addon contains only assets used by these enemies; the exported
whole-game prop catalogue and original sources remain outside the addon.

The detailed asset/provenance report is migration-report.txt. Named inventories
are in audit/models.csv, audit/materials.csv and audit/sounds.csv.

Current install:
Z:\Program Files (x86)\Steam\steamapps\common\GarrysMod\garrysmod\addons\Zombie-Army-Trilogy-DT

Spawn from DT Base > Zombie Army Trilogy. Settings are under
DT Base > Zombie Army > Settings. The director is invisible and needs a navmesh.
The horde UI, music theme/volume, population limit and performance controls remain.
Convars and entity class names keep the za1 prefix for saved-setting compatibility.

Edit addon/lua/za1/zombie_settings.lua for common behavior/balance and
addon/lua/za1/special_settings.lua for special enemies. Gun action windows and
named gun sounds are in addon/lua/za1/ranged_assets.lua. Generated native data
tables are regenerated by the build scripts; keep native asset names intact.

Source models/QCs are under src/zombie, src/specials, src/equipment, src/gibs and
src/props. Materials use VertexLitGeneric. Zombies use model hitgroups rather
than capsules. The separate shared capsule project and DT Base are preserved.

Build prerequisites: Python 3.12, the local AsuraGameBrowser 1.14.1 modules,
NumPy, SciPy, Pillow, fast_simplification, FFmpeg, VTFCmd and Garry's Mod StudioMDL.
Paths for those local tools are in build_za1.py and finish_materials.py.

From this directory:
  python build_trilogy.py
  python build_pipeline.py
  python check_lua.py
  python write_project_report.py
  python validate_trilogy.py
  python install_trilogy.py

For an interrupted object export, use build_trilogy.py --props-only.
For finishing the existing source build, use build_pipeline.py --resume.
For Lua-only edits, rerun check_lua.py and validate_trilogy.py before reinstalling.
The original build_za1.py filename remains a helper-import compatibility detail;
its models command now delegates to the Trilogy exporter.

The installer verifies the complete validated stage and backs up prior active
addons under backups/. It never overlays Trilogy assets into the old addon.
The exact backup and every installed file hash are in audit/installation.json.
Use install_trilogy.py --patch to back up and update changed files in an existing
verified installation without swapping the active addon directory.
Old one-off ZA1 install/capsule migration scripts are under legacy-tools/;
they are historical references, not this project's installation entry points.

Material refresh (2026-10-09): the updated viewer's proved native shader math
now supplies BC5 normal reconstruction/orientation, specular-alpha packing,
native color-space conversion, fitted Phong/tint and diffuse lightwarps.
The exact native shader and local response row must resolve before replacement.
Unsupported shaders keep their current shading, maps and glow unchanged.

under textures/vertexlit so retained shared textures remain intact. The named

Armored Heavy (2026-10-09)
Spawn Armored Heavy under DT Base > Zombie Army Trilogy. The director also
selects them, with a default live/reserved limit of two. Set za1_heavy_limit
in DT Base > Zombie Army > Settings; zero excludes them from director spawns.
They share the existing hearing, navigation, crowd and performance budgets.

The native undead_heavyarmour_burnt actor carries twelve separate armor plates,
with three interchangeable helmet meshes. Native sockets and inverse binds place
each plate. A bullet only damages armor in front of flesh along its ray: exposed
rear areas remain vulnerable, and front plates do not protect flesh from behind.
Breaking shots are fully absorbed; removed plates expose ordinary flesh hitgroups.
Broken plates and their remaining durability persist when the director recycles.
The Heavy gets native headshot gore and one flesh ragdoll, including its remaining
armor. Plate debris is client-side and uses the existing shared cap/lifetime.

Health and durability are addon balance, not verified native BLUE damage values:
health 250; armor 100 per plate, chest 200, stomach 150, back 140 and helmet 160.
Edit the heavy table in addon/lua/za1/special_settings.lua. Armor uses numerical
Source model hitgroups and worn-plate checks on bullet hits, with no extra server
props and no armor bone work in Think. Skeleton armor shares this same code in
addon/lua/za1/armor.lua; its existing settings and behavior are preserved.

Both native walks loop with LX-only walkframes every five frames. Native 90/180
turns, four attacks (including two lunges), emergence, flinches, LODs and ragdoll
constraints are exported. Walking keeps the existing constant gait-speed system;
actions and turns use their extracted root movement. All 143 native animation
events survive. Four shared idle/flinch events refer to sound slots 107/143 absent
from this actor's native HSND tables; they are retained without guessed audio.
Other vocals, footsteps and foley keep native named files. Death voices reuse the
existing named zombie pool. Native damage-property meanings remain unresolved.

Skeleton variants (2026-10-09)
Armored Skeleton and Rotted Skeleton are under DT Base > Zombie Army Trilogy.
Both reuse undead_skeleton_infantry.mdl, the heart weakpoint and twelve bone gibs.
Bodygroup 0 selects the regular/rotted body; 1 is heart; 2 is back; 3 is chest;
4 is helmet (none/closed/open); 5 is unused sword. Groups 6-16 are individual
calf/forearm/hand/shoulder/thigh/pelvis plates. Skin 0/1 selects clean/rusty armor.
The chest needs separate clean/rusty geometry; the rusty loadout keeps its native
clean right gauntlet. Six original armor presets use the native attaching joints.
Skeletons do not equip or drop a sword; the existing armour_sword prop remains.
Fourteen independently removable plates absorb bullets before the heart is
exposed. The breaking shot is fully absorbed. Durability in damage units is
editable in special_settings.lua: chest 80, back 60, pelvis 50, other plates 40.
These are addon balance values. Front and rear plates only protect their own
side. Bullets on exposed bones remain harmless; exposed heart shots kill.
Source bone hitboxes register shots; fitted bone-local worn-plate bounds refine
armor versus body/heart only on a bullet hit. No extra server props or Think-time
bone tests are added. Normal/rotted skeleton anatomy hitboxes are unchanged.
Armored walks use their own two authored clips, LX walkframes every five frames,
and all original foot/vocal/foley markers. Native sound slot 104 is empty and
stays silent. Director weights are editable in special_settings.lua; variants
share the existing skeleton limit and retain broken plates/durability when recycled.
Armor and rotted bones use skin/body-aware bounded client debris, with
complete batches for deaths producing more than fifteen pieces.

Forty-three prop skin families replace 56 redundant models, with unchanged
geometry, UVs, LODs, weights and collision. Native names remain in the prop menu.
See audit/skin-variants.csv for model/skin choices. Old saved prop model paths
must use their replacement model/skin pair in audit/skin-consolidation.json.
The original sources and retired models remain in backups/.
The common cuttable body remains one model. Native camo1/camo2 share UV triangles
across every LOD, but their geometry differs; the cuttable body's UVs also differ.
See audit/uniform-skin-audit.json. Directly swapping native camo textures onto
the current cuttable mesh would not preserve their intended appearance.
